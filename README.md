# Invest Platform

Краудинвестинговая платформа: основатель заводит проект, модератор его проверяет,
инвесторы покупают доли — «тикеты», проект отчитывается о доходах и расходах и платит
дивиденды держателям. Плюс биржа перепродажи тикетов, оплачиваемые работы по проекту с
эскроу, реферальная программа и партнёрка.

Один бэкенд на NestJS и один кодбейс клиента на Expo, который собирается и в мобильное
приложение, и в веб.

- **Веб:** https://invest-platform-web.onrender.com
- **API:** https://invest-platform-api-7msz.onrender.com/api

Интерфейс на трёх языках: армянский (основной), русский, английский.

## Как запустить локально

Нужны Node 20+ и Docker Desktop.

Один скрипт поднимает всё — Postgres в контейнере, бэкенд на `:3000`, веб-клиент на `:80`
— и открывает браузер:

```powershell
.\start.ps1
```

Руками то же самое:

```bash
docker compose up -d postgres
```

```bash
npm --prefix backend install && npm --prefix backend run start:dev
```

```bash
npm --prefix mobile install && npm --prefix mobile run web
```

Первый запуск на пустой базе: `npm --prefix backend run seed` создаёт стартовый набор
аккаунтов и проектов. Регистрация закрыта — войти можно только по инвайт-коду, и первый
в системе аккаунт создаётся без него (иначе платформу невозможно было бы открыть).

### Переменные окружения

`backend/.env` — значения по умолчанию для локальной разработки, в git лежат только
заглушки. Реальные секреты — в `backend/.env.local` (не коммитится) и в дашборде Render.

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Хостинговая база (Neon/Render). Если задана — перебивает `DB_*` и включает TLS |
| `DB_HOST` / `DB_PORT` / `DB_USERNAME` / `DB_PASSWORD` / `DB_NAME` | Локальный Postgres |
| `DB_SYNCHRONIZE` | `true` разрешает TypeORM переписывать схему под сущности при старте. Только для локальной базы, которую не жалко |
| `JWT_SECRET` | Чем подписываются сессии. В production без него приложение не стартует — это намеренно |
| `ADMIN_WIPE_PASSWORD` | Второй замок на `POST /admin/wipe`. Пусто — эндпоинт отказывает всем |
| `WEB_ORIGINS` | Список origin'ов через запятую, которым разрешён CORS. Не задано — отвечаем всем |
| `GOOGLE_WEB_CLIENT_ID` / `_ANDROID_` / `_IOS_` | Аудитории для проверки Google id_token. Все пустые — вход через Google отключён |

Клиент читает `EXPO_PUBLIC_API_URL` (см. `mobile/.env`), по умолчанию `http://localhost:3000/api`.

### Полезные команды

```bash
npm --prefix backend test
```

```bash
npm --prefix backend run migration:run
```

`seed` — базовый набор данных, `reset` — очистка базы, `migration:generate` /
`migration:show` / `migration:revert` — обычный набор TypeORM. Схема на деплое принадлежит
миграциям, а не `synchronize`.

### Бэкенд

22 модуля; ниже те, без которых остальное не читается.

| Модуль | О чём |
| --- | --- |
| `auth` | Регистрация только по инвайту, вход по паролю или Google, JWT на 7 дней. Роли: `investor`, `founder`, `admin` |
| `projects` | Жизненный цикл проекта: `draft` → `pending_review` → `active` → `funded`/`closed`/`rejected`. Правки после публикации тоже идут через модерацию |
| `tickets` | Доли проекта. Покупка на первичном размещении по ценовым раундам и перепродажа между инвесторами |
| `wallets` | Кошелёк: выводимый баланс и невыводимый инвест-кредит, который можно тратить только на тикеты |
| `ledger` | Двусторонняя запись всех движений денег (`money_movements`) и счёт платформы. Пишется в той же транзакции, что и само движение |
| `project-finance` | Доходы, расходы, финансовые отчёты и выплата дивидендов держателям тикетов |
| `project-funding` | Казна проекта и запросы основателя на разблокировку денег под расход — решает модератор |
| `project-works` | Оплачиваемые работы по проекту: заявки, эскроу, вехи, приёмка, споры. Оплата деньгами или тикетами |
| `referrals` | Лестница вознаграждений по уровням приглашений (100/50/10 AMD) и 1% с первого депозита приглашённого |
| `partners` | Заявки на партнёрство и выплаты партнёрам по другой ставке, чем обычным пригласителям |
| `quests` / `activity` | Задания, ежедневный чек-ин, серия дней и общий розыгрыш |
| `notifications` | В базе лежат тип и данные события, текст собирается на клиенте — поэтому уведомления переводятся |
| `logs` | Единая таблица логов: бэкенд, фронтенд, ошибки, запросы к базе. Читается из админки |
| `admin` | Полная очистка платформы и демо-наполнение. Оба — за отдельным паролем |
| `stats` | Сводные цифры и графики для отчётов модератора |

Общее для всех: валидация входа через `class-validator` с whitelist, доступ по гвардам
`JwtAuthGuard` + `RolesGuard`, деньги хранятся в `decimal(14,2)`, а операции, которые их
двигают, идут в транзакции с блокировкой строки кошелька (`common/row-locks.ts`).

## Деплой

`render.yaml` описывает два сервиса на Render: статическая сборка `expo export` для веба и
Node-сервис для API. Миграции выполняются на каждом старте API (`migration:run:prod` в
`startCommand`) — они написаны так, чтобы повторный запуск был безвреден, а упавшая
миграция роняет старт, что и требуется: лучше остановленный деплой, чем половина схемы.

Секреты (`DATABASE_URL`, `JWT_SECRET`, `ADMIN_WIPE_PASSWORD`) задаются в дашборде Render,
а не в файле.

## Что стоит знать, прежде чем править

- **Денег в платёжном смысле пока нет.** `POST /wallet/deposit` начисляет пользователю
  ту сумму, которую он попросил: провайдера платежей не подключали. Это первое, что
  придётся закрыть, когда деньги станут настоящими.
- **Загруженные файлы живут на эфемерном диске Render** и исчезают при каждом деплое.
  Постоянного хранилища у API нет.
- **`synchronize` включается только явно.** Приложение, запущенное против живой базы с
  `DB_SYNCHRONIZE=true`, перепишет ей схему.
- **Логи не имеют срока хранения** — чистятся только кнопкой в админке.
- Тесты покрывают правила, в которых легко ошибиться (реферальная лестница, ценовые
  раунды, розыгрыш, лимиты входа, имена загружаемых файлов), а не проценты покрытия. CI
  пока нет: `npm --prefix backend test` запускается руками.
