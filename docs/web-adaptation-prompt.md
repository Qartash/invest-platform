# Промпт: адаптация под веб (десктоп)

## Контекст

Один Expo-кодбейс (`mobile/`) собирается и в нативное приложение, и в веб через
`react-native-web` (`app.json` → `web.bundler: metro`, `output: single`).
Бэкенд — NestJS (`backend/`), API общий для всех клиентов.

## Задача

Сделать так, чтобы при заходе с десктопного браузера интерфейс выглядел как
веб-приложение, а не как растянутый на весь экран телефон. Нативное приложение
и мобильный браузер при этом не должны измениться ни на пиксель.

## Жёсткие правила

1. **Отдельного API не делать.** Эндпоинты не зависят от устройства. Если для
   десктопа не хватает данных (например, нужен список сразу с деталями, чтобы
   заполнить правую панель) — расширять существующий эндпоинт опциональным
   query-параметром, а не создавать `/web/*`.

2. **`Platform.OS === 'web'` НЕ использовать для раскладки.** Мобильный браузер
   — тоже `'web'`. `Platform.OS` остаётся только для возможностей платформы:
   `linking` в `RootNavigator.tsx`, WebView, image picker, `alert.ts`, hover,
   горячие клавиши.

3. **Раскладка решается шириной окна** через `useWindowDimensions()` — он
   пересчитывается при ресайзе окна, в отличие от `Dimensions.get()`.
   `Dimensions.get()` для раскладки не применять.

4. **Ничего не ломать на мобильном.** Всё ниже брейкпоинта `md` должно
   рендериться ровно так же, как сейчас.

## Порядок работы

### Шаг 1 — фундамент (без этого остальное бессмысленно)

- В `src/theme/tokens.ts` добавить брейкпоинты: `sm: 600`, `md: 900`, `lg: 1280`.
- Сделать хук `src/theme/useBreakpoint.ts` на `useWindowDimensions()`, отдающий
  что-то вроде `{ width, isCompact, isMedium, isWide }`. Один источник правды —
  дальше по компонентам голые числа не сравнивать.
- Добавить контейнер-обёртку с `maxWidth` и центровкой (условно
  `src/components/ui/PageContainer.tsx`), чтобы контент не растягивался на 2560px.
  Захардкоженные `maxWidth` в `DatePickerModal.tsx:155`,
  `ProjectFinancePanel.tsx:1404`, `ProjectWorksPanel.tsx:947` перевести на токены.

### Шаг 2 — навигация

- `MainNavigator.tsx` использует `createBottomTabNavigator` с кастомным
  `BottomDock`. На широком экране нижний док — неправильный паттерн: нужен
  боковой рейл/сайдбар слева. Реализовать так, чтобы `BottomDock` сам
  переключался на боковой режим по брейкпоинту, либо подменять `tabBar`.
  Навигационное состояние и имена роутов не менять — иначе поломается
  `linking.ts`.
- Проверить, что глубокие ссылки из `linking.ts` продолжают работать: перезагрузка
  страницы на любом роуте, кнопка «назад» браузера, шаринг URL.
- Заголовки экранов: сейчас `headerShown: false`. Для десктопа решить, нужен ли
  верхний бар с брендом/языком/профилем, и если да — только на широком экране.

### Шаг 3 — экраны

Пройтись по всем экранам в `src/screens/` и для каждого решить, что делает
широкий экран. Не пропустить ни один:

- `auth/`: `LoginScreen`, `RegisterScreen` — центрированная карточка формы,
  а не форма во всю ширину.
- `investor/`: списки проектов → сетка в 2–3 колонки вместо одной; карточка
  проекта → мастер-деталь (список слева, детали справа) там, где это уместно.
- `founder/`: `CreateProjectScreen`, `ProjectFinanceScreen`, `ProjectWorksScreen`
  — формы в две колонки, длинные таблицы наконец помещаются целиком.
- `admin/`: экраны модерации и `LogsScreen` — здесь десктоп даёт больше всего,
  таблицы должны стать настоящими таблицами.
- `ProfileScreen`, `EditProfileScreen`, `ReportsScreen`.

### Шаг 4 — модалки и оверлеи

Все `*Modal.tsx` в `src/components/` сейчас рассчитаны на телефон
(bottom-sheet / полный экран). На десктопе они должны быть центрированными
диалогами ограниченной ширины с закрытием по Escape и по клику вне.
Список: `AvatarPickerModal`, `BuyListingModal`, `DatePickerModal`, `HintModal`,
`InvestorProfileModal`, `InvestorsListModal`, `ProjectHistoryModal`,
`RiskLevelModal`, `SellTicketModal`, `ActionSheet`.

### Шаг 5 — веб-специфика (вот здесь `Platform.OS === 'web'` уместен)

- Hover-состояния на кнопках, карточках, строках списков — на телефоне их нет,
  на десктопе их отсутствие выглядит как сломанный сайт.
- Видимый focus-ring для навигации с клавиатуры, Tab-порядок в формах,
  submit по Enter.
- Курсор `pointer` на кликабельном.
- Скролл: на десктопе скроллит колесо, проверить что вложенные `ScrollView`
  не перехватывают его.
- `RichTextEditor.tsx` / `RichTextView.tsx` на `@10play/tentap-editor` через
  WebView — на вебе поведение отличается, проверить отдельно.
- `favicon`, `<title>` (уже частично есть через `documentTitle` в `linking.ts`),
  мета-теги.

### Шаг 6 — проверка

Не отчитываться о готовности без прогона. Проверить в браузере на ширинах
375 / 768 / 1280 / 1920, в светлой и тёмной теме (`ThemeProvider.tsx`), на всех
трёх языках (`en` / `hy` / `ru` — армянский и русский длиннее английского и
ломают узкие кнопки). Отдельно убедиться, что мобильный браузер на 375px
выглядит как раньше.

## Чего НЕ делать

- Не создавать второе приложение / отдельный веб-фронтенд.
- Не форкать компоненты на `Foo.tsx` + `Foo.web.tsx`, если разница — это пара
  стилей. Файловый сплит только там, где реализации действительно расходятся.
- Не трогать бизнес-логику, стор (`src/store/`) и слой `src/api/`.
- Не менять имена роутов и структуру навигации.

## Отчёт

По каждому шагу — что сделано, что осталось. Если что-то решено не делать,
сказать прямо, а не умолчать.
