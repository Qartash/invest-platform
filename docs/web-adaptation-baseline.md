# Эталон мобильной раскладки (до адаптации под веб)

Снято на коммите шага 1 — шаг 1 визуально ничего не менял, поэтому это состояние
«до». Используется шагом 6 для проверки регрессии.

Скриншоты в этой среде снять не удалось (панель браузера не отрисовывает кадры),
поэтому эталон снят как геометрия DOM. Для регрессии это даже точнее скриншота:
расхождение видно в пикселях и с указанием элемента.

## Как снять слепок

Открыть нужный экран в веб-сборке, выставить ширину окна, выполнить в консоли:

```js
(() => {
  const out = [];
  document.querySelectorAll('body *').forEach((el) => {
    const r = el.getBoundingClientRect();
    if (r.width === 0 && r.height === 0) return;
    const txt = el.children.length === 0 ? (el.textContent || '').trim().slice(0, 40) : '';
    out.push([Math.round(r.x), Math.round(r.y), Math.round(r.width), Math.round(r.height), el.tagName, txt].join('|'));
  });
  return { w: window.innerWidth, count: out.length, rows: out };
})()
```

Формат строки: `x|y|width|height|tag|text`.

## Проверять только перезагрузкой, не ресайзом

В панели браузера Claude Code смена размера вьюпорта идёт через CDP и **не
порождает событий resize**: замерено — `visualViewport.resize` 0 срабатываний,
`window.resize` 0, при том что `innerWidth` и `visualViewport.width` уже новые.

react-native-web слушает именно `visualViewport` (`Dimensions/index.js`), поэтому
`useWindowDimensions` не обновляется и раскладка остаётся от прошлой ширины.
Выглядит как баг адаптива, но это артефакт стенда — в настоящем браузере
перетаскивание окна событие порождает.

Порядок такой: выставить ширину → **перезагрузить страницу** → замерять.
Замер сразу после ресайза даёт раскладку от предыдущей ширины.

Из того же следует: «плавный» переход через брейкпоинт на этом стенде не
проверяется вообще. Если он важен — только вручную в обычном браузере.

Форма растянута во всю ширину: карточка 1232px при окне 1280 (поля ввода на весь
экран). Горизонтального переполнения нет — `document.scrollWidth` = 1280.
